# 用户使用手册写作规则

本规则用于支撑 `write-user-manual` skill 的正文写作。核心目标是让最终用户只依赖手册，就能正确、稳定、独立完成软件操作。

## 1. 章节组织

第 4 章“软件操作指南”默认按功能模块组织，适用于功能边界清晰、模块化程度高的软件。

推荐层级：

```text
4. 软件操作指南
  4.1 用户管理模块
    4.1.1 用户登录
    4.1.2 新增用户
    4.1.3 修改用户信息
  4.2 数据管理模块
    4.2.1 数据导入
    4.2.2 数据导出
```

组织要求：
- 优先保证“模块”边界清晰，再安排操作顺序。
- 目录层级不超过三级。
- 一个操作名称只指向一个用户目标，不把多个动作混在同一节。
- 同类操作使用统一命名，例如“新增用户”“修改用户”“禁用用户”。

## 2. 最小操作单元结构

每个操作单元至少包含以下四部分，必要时补充“前置条件”和“警告/注意”。

### 2.1 功能概述

要求：
- 说明该功能是什么，以及为什么使用。
- 篇幅控制在 1 到 3 句话。
- 使用用户视角语言，不写实现机制。

示例：

```markdown
新增用户功能用于创建系统访问账户。通过此功能，管理员可以为新入职人员分配登录账号和初始权限，使其能够访问授权范围内的系统功能。
```

### 2.2 操作步骤

要求：
- 按顺序编号，使用 `1. 2. 3.` 格式。
- 每一步只写一个明确动作。
- 在步骤前单独说明前置条件。
- 界面元素名称必须与实际界面一致。
- 必填项、格式要求、长度限制、取值范围必须写清楚。
- 存在分支时分别说明。
- 关键界面引用截图编号。

推荐写法：

```markdown
**前置条件**：
- 当前登录账号具有“用户管理”权限。
- 已进入“用户管理”页面（操作路径：【系统管理】>【用户管理】）。

**操作步骤**：
1. 在“用户管理”页面，点击页面右上角的【新增】按钮。
2. 系统弹出“新增用户”对话框（如图 4-2 所示）。
3. 填写用户信息：
   - 用户名：必填，6-20 位字母或数字，不可重复。
   - 登录口令：必填，长度不少于 8 位，且至少包含三类字符。
   - 角色：必选，从下拉列表中选择。
4. 点击【确定】按钮提交。
5. 系统校验通过后完成新增。
```

### 2.3 输出/结果

要求：
- 描述正常情况下的提示信息、页面变化、数据变化和后续状态。
- 尽量写出用户直接可见的系统反馈。

示例：

```markdown
**输出/结果**：
- 系统弹出“新增成功”提示，3 秒后自动消失。
- 对话框自动关闭，页面返回“用户管理”列表。
- 用户列表自动刷新，新增用户显示在列表中，状态为“启用”。
```

### 2.4 异常处理

要求：
- 优先列常见异常和高频错误，不追求穷尽所有技术异常。
- 写清楚异常现象、可能原因和处理方法。
- 建议使用表格表达。

推荐表头：

| 异常现象 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 提示“用户名已存在” | 用户名已被占用 | 更换用户名后重新提交 |

## 3. 语言规范

### 3.1 行文风格

- 使用主动语态，例如“点击【保存】按钮”。
- 使用祈使句，直接告诉用户执行什么动作。
- 不使用开发术语或内部实现术语。
- 不使用模糊表达，如“适当调整”“快速完成”“系统自动处理相关逻辑”。

### 3.2 术语一致性

- 同一对象全文只用一个名称。
- 菜单名、按钮名、字段名、对话框名必须与界面一致。
- 如果产品中确有两个近义对象，例如“用户”和“账户”，先给出定义，再固定使用。

## 4. 界面元素引用规范

| 元素类型 | 引用格式 | 示例 |
| --- | --- | --- |
| 按钮 | 【按钮名称】 | 点击【确定】按钮 |
| 菜单 | 【菜单项】>【子菜单】 | 选择【系统管理】>【用户管理】 |
| 选项卡 | “选项卡名称” | 切换到“基本信息”选项卡 |
| 输入框 | “字段名称”输入框 | 在“用户名”输入框中输入 |
| 对话框 | “对话框名称”对话框 | 弹出“新增用户”对话框 |
| 快捷键 | `<键名>+<键名>` | 按 `<Ctrl>+<S>` 保存 |

## 5. 警告与注意事项

以下操作应强制评估是否需要警示语：
- 删除
- 禁用
- 权限变更
- 覆盖导入
- 批量执行
- 数据提交后不可撤回

推荐格式：

```markdown
⚠️ **警告**：删除用户操作不可恢复，请谨慎执行。
```

```markdown
🔴 **注意**：禁用用户后，该用户将立即无法登录系统，正在进行的任务可能被中断。
```

写法要求：
- 写清楚风险对象。
- 写清楚影响结果。
- 写清楚用户应采取的确认动作或规避方法。

## 6. 截图使用规则

- 关键操作界面应配截图。
- 截图编号与章节编号保持一致，例如“图 4-1”“图 4-2”。
- 步骤中引用的截图编号必须在图注中存在。
- 图中界面内容应与正文中的按钮、字段和提示语一致。
- 如果截图尚未提供，写为 `截图待补充`，不要伪造图号。
