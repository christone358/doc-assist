# 需求规格文档编写



本 Skill 帮助用户编写软件需求规格文档（SRS），覆盖系统或模块的功能需求和非功能需求。
通过集成项目事实信息（用例清单、功能模块清单），确保文档内容与项目实际保持一致。

## 能力范围

### 支持
- 编写新的需求规格文档
- 基于已有版本进行精准修改
- 从项目事实信息中提取用例和功能说明
- 生成用户故事和验收标准

### 不支持
- 生成 UML 图（仅文字描述）
- 自动获取代码实现细节

## 输入要求

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| project_module | string | 是 | 要编写需求的目标模块 |
| base_version | string | 否 | 待修改的文档路径（精准修改用） |

## 输出规范

生成的需求规格文档包含：
1. 文档信息（标题、版本、日期）
2. 概述（目的、范围、定义）
3. 功能需求（按模块分章节）
4. 非功能需求（性能、安全、可用性等）
5. 约束条件
6. 附录

## 工作原理

编写需求规格文档时，本 Skill 最主要依赖**用例描述（usecases）**——包括用户与系统的交互流程、参与角色、主流程步骤、异常处理和前后置条件。用例信息是生成准确需求条目的核心来源，缺少它将无法编写出与项目实际一致的文档。

同时需要了解**功能模块描述（modules）**，以明确模块职责、关键特性和功能范围，确保需求文档覆盖模块的完整功能边界。

在描述具体操作步骤和界面交互细节时，如果能参考**原型界面（prototypes）**，可以更准确地描述界面行为和用户操作流程。如果需要描述系统对外接口或输入输出规范，参考**接口清单（interfaces）**也会有所帮助。

**推荐加载顺序**：先通过 get_fact_overview("modules") 和 get_fact_overview("usecases") 定位写作目标，再通过 get_fact_detail 加载具体模块的用例详情和功能描述，按需补充接口或原型信息。

## 使用示例

用户输入："帮我写用户认证模块的需求规格文档"

Agent 调用参数：
```json
{
  "project_module": "用户认证模块",
  "base_version": null
}
```
