# 需求规格文档编写



本 Skill 帮助用户编写软件需求规格文档（SRS），覆盖系统或模块的功能需求和非功能需求。
通过集成项目事实信息（用例清单、功能模块清单），确保文档内容与项目实际保持一致。

## 能力范围

### 支持
- 编写新的需求规格文档
- 基于已有版本进行精准修改
- 从项目事实信息中提取用例和功能说明
- 生成用户故事和验收标准

### 不支持
- 生成 UML 图（仅文字描述）
- 自动获取代码实现细节

## 输入要求

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| project_module | string | 是 | 要编写需求的目标模块 |
| base_version | string | 否 | 待修改的文档路径（精准修改用） |

## 输出规范

生成的需求规格文档包含：
1. 文档信息（标题、版本、日期）
2. 概述（目的、范围、定义）
3. 功能需求（按模块分章节）
4. 非功能需求（性能、安全、可用性等）
5. 约束条件
6. 附录

## 工作原理

编写需求规格文档时，本 Skill 需要充分了解目标模块的用例信息（用户与系统的交互流程、角色、主流程、异常处理），以及该模块的功能描述（模块的职责、关键特性）。这些信息是生成准确需求条目的基础，缺少它们将无法编写出与项目实际一致的文档。

在描述具体操作步骤和交互细节时，如果能参考原型界面，可以更准确地描述界面行为和用户操作流程。如果需要描述系统的输入输出规范，参考接口清单也会有所帮助。

## 使用示例

用户输入："帮我写用户认证模块的需求规格文档"

Agent 调用参数：
```json
{
  "project_module": "用户认证模块",
  "base_version": null
}
```
