# 模块级用户使用手册结构规范

本文件定义 `user-manual-writter` 的唯一正文结构。正文必须严格遵循本结构，不得自行增加整本手册章节，也不得改写为跨模块汇编格式。

## 1. 适用范围

仅适用于单个软件模块的用户使用手册或模块级操作手册。

- 一个文档只描述一个模块。
- 文档主体围绕该模块的操作单元展开。
- 若用户请求整本手册，本结构不适用。

## 2. 正文结构

正文默认采用以下固定骨架：

```markdown
# <系统名称><模块名称>用户使用手册

# 4. 软件操作指南

### 4.1 <模块名称>
#### 4.1.1 <子模块名称>
#### 4.1.1.1 功能概述
#### 4.1.1.2 前置条件
#### 4.1.1.3 操作步骤
#### 4.1.1.4 输出/结果
#### 4.1.1.5 异常处理
#### 4.1.1.6 警告/注意

### 4.1.2 <子模块名称>
...

```

## 3. 各章节要求

### 3.1 骨架内的标题要求

- 章节4，标题固定为：软件操作指南
- 二级标题4.x，以模块名称命名，不增加系统、子系统名称作为前缀，不增加后缀；
- 三级标题按子模块名称命名，不得增加前缀、后缀。
- 
### 3.2 二级标题下的模块写作说明

写明：

- 可以在4.X的模块名称下，总结一段模块的整体功能描述，覆盖左右子模块。非必须，可裁剪。
- 模块级别的整体功能描述，重点在于描述该模块在系统中的职责与边界、面向的用户对象、解决的业务问题或价值。
- 模块的总结必须依据模块内写明的事实信息进行总结，不得凭空创造和发挥。
- 不要写实现架构、接口机制、数据库设计或部署信息。

### 3.3 子模块写作说明

- 这是使用手册的正文主体。
- 每个子模块作为最小描述单元，严格按照正文结构章节中的目录结构和内容编写。子模块作为最小单元描述，每个必须包含：
  - `功能概述`
  - `前置条件`
  - `操作步骤`
  - `输出/结果`
  - `异常处理`
  - `警告/注意` 

#### 3.3.1 前置条件

写明：

- 可执行该模块操作的角色或权限范围。
- 使用前的环境条件、数据准备条件或业务前提。
- 必要的入口条件，例如已登录系统、已具备相应权限。

#### 3.3.2 操作步骤

操作步骤是对该子模块的功能以业务操作视角进行描述。需要对子模块下的功能按用户实际操作步骤的方式进行描述，应覆盖所有功能项，不得遗漏。不得臆造、创造不存于模块和子模块详细功能描述中的内容。不得扩大、改变事实信息中的功能描述。
  

#### 3.3.3 输出/结果

- 描述操作成功后的界面变化、数据变化、系统响应。
- 说明系统给出的成功提示信息
- 说明操作后进入什么状态（如“用户列表自动刷新，新增用户出现在列表末尾”）

#### 3.3.4 异常处理

列出用户操作过程中可能遇到的典型错误场景，描述用户看到的现象（如“系统提示‘用户名已存在’”），简要说明发生该异常的原因。告诉用户如何解决（如“请更换用户名后重新提交”）。

## 4. 编排规则

- 先写模块层说明，再写操作单元。
- 操作单元按用户自然流程或高频使用顺序排列。
- 一个操作单元只描述一个明确用户目标，不混合多个任务。
- 不在正文中插入“事实来源说明”“质量检查结论”“待确认项汇总”作为新章节。

## 5. 可省略与不可省略项

### 不可省略

- 正文默认采用以下固定骨架中，所有章节不可省略，即使没有内容，也不得删除标题。


## 6. 严格禁止

- 禁止输出整本手册式章节，如“引言”“系统概述”“附录”“部署说明”。
- 禁止输出跨模块的能力说明。
- 禁止把过程说明、思考说明或审校说明混入正文。
- 禁止为凑结构而新增无事实支撑的操作单元。
