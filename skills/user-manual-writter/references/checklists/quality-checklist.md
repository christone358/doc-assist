# 模块级用户使用手册质量检查清单

本清单用于 `user-manual-writter` 的写作后自检。用于内部校验，不写入正文。

## 一、任务模式识别

- [ ] `MODE-001` 已明确识别本次任务属于 `create`、`partial-update` 或 `revise-from-base`
- [ ] `MODE-002` 已明确目标模块唯一命中，或在存在歧义时已先向用户确认
- [ ] `MODE-003` 已明确本轮输出范围：完整模块正文、局部段落修订，或基于基线版本优化

## 二、范围边界

- [ ] `SCOPE-001` 内容仅覆盖一个目标模块
- [ ] `SCOPE-002` 未扩写无关模块、全系统概述或整本手册其他章节
- [ ] `SCOPE-003` `partial-update` 仅修改用户指定的小节、段落或编号范围
- [ ] `SCOPE-004` `revise-from-base` 仅修改受影响区域，未借机重写无关内容

## 三、上下文与事实加载

- [ ] `FACT-001` 已先定位目标模块，并确认模块 ID、所属系统或所属子系统信息
- [ ] `FACT-002` 已读取与目标模块相关的用户场景、业务用例或操作任务
- [ ] `FACT-003` 在需要时已补充读取界面原型、交互说明、字段定义、系统反馈或校验规则
- [ ] `FACT-004` `create` 未加载无关历史版本
- [ ] `FACT-005` `partial-update` 仅加载目标局部所需事实
- [ ] `FACT-006` `revise-from-base` 已先读取基线版本，再进入修订
- [ ] `FACT-007` 未编造菜单路径、按钮名、字段名、提示文案、异常场景或权限规则
- [ ] `FACT-008` 未把实现细节冒充为用户可见事实

## 四、结构完整性

### 4.1 `create` 结构检查

- [ ] `STRUCT-C-001` 正文以 `# <系统名称><模块名称>用户使用手册` 开头，或在缺失系统名称时使用同等标题格式
- [ ] `STRUCT-C-002` 包含 `# 4. 软件操作指南`
- [ ] `STRUCT-C-003` 至少包含一个 `### 4.x <模块名称>`
- [ ] `STRUCT-C-004` 每个模块标题下至少包含一个 `#### 4.x.y <子模块名称>`
- [ ] `STRUCT-C-005` 每个子模块均包含 `功能概述`
- [ ] `STRUCT-C-006` 每个子模块均包含 `前置条件`
- [ ] `STRUCT-C-007` 每个子模块均包含 `操作步骤`
- [ ] `STRUCT-C-008` 每个子模块均包含 `输出/结果`
- [ ] `STRUCT-C-009` 每个子模块均包含 `异常处理`
- [ ] `STRUCT-C-010` `警告/注意` 已按当前结构要求保留

### 4.2 `partial-update` 结构检查

- [ ] `STRUCT-P-001` 输出结构与用户指定范围一致
- [ ] `STRUCT-P-002` 未因为局部任务强行补全无关章节
- [ ] `STRUCT-P-003` 若输出目标小节正文，其标题编号与既有结构保持一致

### 4.3 `revise-from-base` 结构检查

- [ ] `STRUCT-R-001` 已继承基线版本的原有结构和编号体系
- [ ] `STRUCT-R-002` 若基线结构与当前 reference 不一致，已优先保持原文稳定
- [ ] `STRUCT-R-003` 仅在用户明确要求重构时才调整既有结构

## 五、步骤可执行性

- [ ] `STEP-001` 操作步骤按自然顺序编号，使用 `1. 2. 3.` 形式
- [ ] `STEP-002` 每一步只描述一个动作
- [ ] `STEP-003` 页面入口或操作起点清晰
- [ ] `STEP-004` 输入项规则在有事实支撑时写明
- [ ] `STEP-005` 分支场景已明确拆开
- [ ] `STEP-006` 用户仅依据文档即可复现主要操作

## 六、结果与异常

- [ ] `RESULT-001` 成功结果写明系统反馈，或明确标注 `待补充系统反馈文案`
- [ ] `RESULT-002` 成功结果写明页面变化或数据变化
- [ ] `RESULT-003` 异常处理覆盖高频用户问题
- [ ] `RESULT-004` 异常处理内容未超出事实信息支持范围
- [ ] `RESULT-005` `警告/注意` 写明风险对象、影响后果和确认动作

## 七、缺口处理

- [ ] `GAP-001` 缺少界面入口时使用 `需确认界面路径`
- [ ] `GAP-002` 缺少字段明细时使用 `待补充字段规则`
- [ ] `GAP-003` 缺少系统反馈时使用 `待补充系统反馈文案`
- [ ] `GAP-004` 缺少截图时使用 `截图待补充`
- [ ] `GAP-005` 缺口标记嵌入对应段落，未单独扩成说明章节

## 八、术语与风格

- [ ] `LANG-001` 全文使用终端用户视角
- [ ] `LANG-002` 全文术语统一
- [ ] `LANG-003` 界面元素命名格式统一
- [ ] `LANG-004` 使用主动语态和祈使句或客观说明句
- [ ] `LANG-005` 未出现开发术语、内部实现术语或营销式表达
- [ ] `LANG-006` 语气严肃、严格、专业

## 九、输出洁净度

- [ ] `OUTPUT-001` 正文中没有“编写说明”
- [ ] `OUTPUT-002` 正文中没有“事实来源说明”
- [ ] `OUTPUT-003` 正文中没有“执行摘要”
- [ ] `OUTPUT-004` 正文中没有“质量检查结论”
- [ ] `OUTPUT-005` 正文中没有思考过程、工具调用过程或判断过程

## 十、结项标准

仅当与当前任务模式相关的检查项满足时，才可视为本轮模块级用户使用手册输出完成。
