# 项目事实信息浏览验收清单

本文档用于验收 `simplify-project-facts-maintenance` 的浏览与维护链路，覆盖模块档案渐进维护、模块浏览界面和原型集中存放关联。

## 场景 1：真实业务模块的渐进维护

样例模块：

- `project-facts/modules/业务保障管理系统-保障资产管理.md`

验收步骤：

1. 打开模块档案，确认已存在功能描述和功能点，但 `API 清单`、`页面 / 原型`、`包 / 类` 仍为待补充状态。
2. 向 `API 清单` 表格增加一行，例如：

```markdown
| 云主机资产查询接口 | 查询云主机资产列表 | /api/cloud-hosts | GET |
```

3. 刷新派生视图与索引。
4. 打开“项目事实信息”页面，搜索“保障资产管理”。
5. 确认右侧详情能展示：
   - 既有功能描述和功能点
   - 新增的 API 清单行
   - 仍为空的页面 / 原型、包 / 类章节

通过标准：

- 同一模块档案在产品先写功能点、研发后补 API 的情况下可以持续演进
- 浏览界面无需录入模块 ID，即可看到更新后的模块详情

## 场景 2：原型整包集中存放与页面名称关联

样例原型包：

- 在 `project-facts/prototypes/axure-export/` 下放入一个 Axure 风格目录
- 至少包含：
  - `index.html`
  - `云主机列表页.html`
  - `云主机详情页.html`

样例模块档案写法：

```markdown
## 页面 / 原型
- 云主机列表页
- 云主机详情页
```

验收步骤：

1. 把样例原型包整体放入 `project-facts/prototypes/axure-export/`。
2. 在目标模块档案中填写页面名称列表。
3. 刷新派生视图与索引。
4. 检查 `project-facts/prototypes/page-index.json`，确认生成了页面名称与 HTML 相对路径的映射。
5. 打开“项目事实信息”页面，进入对应模块详情。
6. 确认“页面 / 原型”章节展示页面名称，并在匹配成功时显示集中原型资源的相对路径。

通过标准：

- 原型资源无需按模块拆分
- 模块档案只维护页面名称即可建立浏览关联

## 场景 3：模块浏览界面

验收步骤：

1. 打开“项目事实信息”页面。
2. 确认左侧默认展示模块列表，而不是按 layer 平铺的事实条目。
3. 使用关键词搜索、系统筛选、状态筛选。
4. 点击任意模块，确认右侧详情展示：
   - 功能描述
   - 功能点
   - API 清单
   - 页面 / 原型
   - 包 / 类
   - 依赖模块
   - 备注

通过标准：

- 浏览视角与维护视角一致，均以模块为中心
- 用户能够直接看到当前知识库里已经维护的事实信息
