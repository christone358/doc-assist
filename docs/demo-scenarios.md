# 演示场景脚本

## 演示前准备

1. 确保系统已启动：`./start.sh`
2. 确保已配置至少一个 LLM（DeepSeek 或 QWen）
3. 确保 `skills/` 下已安装示例 Skill（write-requirements、write-design、write-test-plan）

---

## 场景一：LLM 配置演示

**目标**：展示如何配置 DeepSeek 和 QWen 模型，并切换默认模型

**步骤**：

1. 打开系统，进入「⚙️ LLM 配置」
2. 点击「添加配置」，填写 DeepSeek 信息：
   - 名称：`DeepSeek V3`
   - 服务商：`DeepSeek`
   - 模型：`deepseek-chat`
   - API 地址：`https://api.deepseek.com/v1`
   - Token：（填写真实 Key）
3. 点击「测试连接」→ 出现「连接成功」提示
4. 保存并设为默认
5. 重复添加 QWen 配置（`qwen-plus`）
6. 演示切换默认模型

**关键演示点**：
- API Key 显示为掩码（`sk-****xxxx`），安全存储
- 测试连接实时验证 API 可用性
- 可随时切换使用的模型

---

## 场景二：新增文档编写（多轮对话）

**目标**：通过多轮对话逐步完善需求规格文档，展示事实信息推荐

**步骤**：

1. 进入「💬 对话」，点击「+ 新对话」
2. 输入：
   > 帮我为用户认证模块编写需求规格文档

3. 观察 Agent 处理流程：
   - 状态提示：「正在理解需求...」→「正在选择 Skill...」→「正在生成...」
   - Skill 被激活（write-requirements）
   - LLM 开始流式输出

4. 文档生成后，输入追加需求：
   > 请补充密码强度要求：至少 8 位，包含大小写字母和数字

5. Agent 在上一版本基础上修改，输出新版本

6. 进入「📁 文档」查看两个版本的历史记录

**关键演示点**：
- 流式输出（文字逐字出现）
- Skill 自动匹配（识别"需求"→选择 write-requirements）
- 文档路径自动展示
- 多轮对话上下文保持

---

## 场景三：精准修改演示

**目标**：演示基于已有文档的精准修改流程

**步骤**：

1. 基于场景二的文档，在同一对话中输入：
   > 修改密码最小长度为 12 位，并增加"密码不能包含用户名"的约束

2. Agent 识别修改意图，加载最新版本
3. 精准定位修改位置，生成新版本
4. 在「📁 文档」中比较两个版本的差异

**关键演示点**：
- 修改意图识别（"修改"关键词触发）
- 保留原文档结构，只修改相关部分
- 版本号自动递进（v1.0.0 → v1.0.1）

---

## 场景四：事实信息展示

**目标**：演示项目事实信息的浏览和在文档生成中的应用

**步骤**：

1. 进入「🗂 事实信息」
2. 展示按系统 / 子系统分组的模块档案列表
3. 使用关键词搜索「用户」，展示搜索结果
4. 点击查看某条记录的详细信息
5. 切换回「💬 对话」，输入含项目事实关联的需求：
   > 根据系统中的用户认证模块，生成测试方案文档

**关键演示点**：
- 事实信息按模块档案聚合展示，易于浏览
- Agent 自动将相关事实信息注入 LLM 上下文
- 生成的文档内容基于项目实际信息

---

## 场景五：模型切换演示

**目标**：展示在 DeepSeek 和 QWen 之间切换

**步骤**：

1. 进入「⚙️ LLM 配置」
2. 当前默认：DeepSeek V3
3. 点击 QWen 配置的「设为默认」
4. 返回「💬 对话」，新建一个对话
5. 发送消息，观察响应（由 QWen 生成）
6. 切换回 DeepSeek，对比响应风格

**关键演示点**：
- 切换模型不需要重启系统
- 历史对话仍可查看
- 不同模型的响应风格对比
