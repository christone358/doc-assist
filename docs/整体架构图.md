## 2. 写作场景执行链路图

```mermaid
sequenceDiagram
    participant U as 用户
    participant FE as 前端 Web UI
    participant BE as 后端 FastAPI
    participant MA as 主 Agent
    participant SA as Skill 子 Agent
    participant MCP as MCP Runtime
    participant PF as 项目知识库
    participant DV as 历史文档
    participant SK as Skill 资源
    participant LLM as LLM

    U->>FE: 发起写作请求
    FE->>BE: REST / WebSocket 消息
    BE->>MA: 创建当前轮次上下文并启动主 Agent
    MA->>LLM: 意图判断、Skill 选择

    alt 查询型请求
        MA->>MCP: 调用 facts.* / docs.* / prototypes.*
        MCP->>PF: 读取模块事实 / 原型信息
        MCP->>DV: 读取历史文档元数据或内容
        MCP-->>MA: 返回结构化结果
        MA-->>BE: 直接生成答复
    else 写作型请求
        MA->>SA: execute_skill(skill_id, user_intent)
        SA->>LLM: 按 Skill 规范规划执行
        SA->>SK: 读取 SKILL.md / references / templates / scripts
        SA->>MCP: 加载 facts.* / docs.* / prototypes.*
        MCP->>PF: 读取目标模块聚合根事实
        MCP->>DV: 读取历史正式版本
        MCP-->>SA: 返回运行时上下文
        SA->>LLM: 生成或修订正文
        SA-->>MA: 返回执行摘要与草稿状态
        MA-->>BE: 汇总结果
    end

    BE-->>FE: 流式返回文本与执行状态
    FE-->>U: 展示结果与可观测过程
```

## 3. 设计关系解读

- 主 Agent 是编排中心，负责判断“要做什么”，但不负责完整写作执行。
- Skill 子 Agent 是执行中心，负责判断“具体怎么写”，并消费事实、历史文档和 Skill 私有资源。
- MCP Runtime 是统一访问层，负责把知识库、原型、历史文档等资源暴露成稳定工具。
- 项目知识库是事实底座，当前以“模块聚合根”为核心组织方式。
- LLM 不直接等于系统架构本身，而是被嵌入主 Agent 和子 Agent 两类角色中发挥作用。
