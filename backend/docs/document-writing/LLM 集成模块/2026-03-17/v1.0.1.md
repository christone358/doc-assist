# 需求规格说明书 (SRS)

**文档版本：** V1.0
**修订日期：** 2024-05-27
**项目模块：** 用户认证模块

---

## 1. 文档概述

### 1.1 目的
本文档旨在定义“用户认证模块”的功能性需求，作为系统设计、开发、测试和验收的依据。本文档的目标读者包括项目经理、产品经理、开发人员、测试人员及相关干系人。

### 1.2 范围
本文档涵盖用户认证模块的核心功能，包括用户注册、登录、密码管理、会话管理及第三方账号登录。不涉及用户个人资料管理、权限控制等超出认证范畴的功能。

### 1.3 定义与缩写
| 术语 | 定义 |
| :--- | :--- |
| SRS | 软件需求规格说明书 (Software Requirements Specification) |
| JWT | JSON Web Token，一种用于安全传输信息的开放标准 |
| OAuth 2.0 | 一个开放授权标准，允许用户授权第三方应用访问其存储在另一服务提供者的信息 |
| MFA | 多因素认证 (Multi-Factor Authentication) |

## 2. 总体描述

### 2.1 产品愿景
为用户提供安全、便捷、可靠的身份认证服务，保障系统入口安全，提升用户体验。

### 2.2 用户角色
| 角色 | 描述 |
| :--- | :--- |
| 未注册访客 | 尚未拥有系统账号的用户，可进行注册操作。 |
| 已认证用户 | 已完成注册并登录系统的用户，可进行登录、登出、修改密码等操作。 |
| 系统管理员 | 拥有后台管理权限，可管理用户账号（如禁用、重置密码）。 |

### 2.3 假设与依赖
*   假设用户拥有有效的电子邮箱或手机号。
*   依赖第三方短信/邮件服务提供商以发送验证码。
*   依赖第三方OAuth服务提供商（如微信、GitHub）以实现社交登录。

## 3. 功能需求

### 3.1 用户注册 (FR-01)
**描述：** 允许未注册访客通过邮箱或手机号创建新账户。
**优先级：** 高

**用户故事：**
*   作为一个未注册访客，我希望通过邮箱和密码进行注册，以便使用系统的核心功能。
*   作为一个未注册访客，我希望通过手机号和短信验证码进行注册，以便快速完成账户创建。

**验收标准：**
*   AC-01.1：注册页面应提供“邮箱注册”和“手机号注册”两种方式选项。
*   AC-01.2：邮箱注册时，用户必须输入有效的邮箱地址、符合安全策略的密码，并确认密码。
*   AC-01.3：邮箱注册提交后，系统应向该邮箱发送一封包含激活链接的邮件。
*   AC-01.4：用户点击激活链接后，账户状态应变为“已激活”，并自动跳转至登录页面或首页。
*   AC-01.5：手机号注册时，用户必须输入有效的手机号，并点击“获取验证码”。
*   AC-01.6：系统应向用户手机发送一条包含6位数字验证码的短信，验证码有效期为5分钟。
*   AC-01.7：用户输入正确的验证码后，需设置密码并完成注册，账户状态即为“已激活”。
*   AC-01.8：系统必须校验邮箱/手机号的唯一性，重复注册应给出明确提示。
*   AC-01.9：密码必须满足预设的复杂度要求（如至少8位，包含字母和数字）。

### 3.2 用户登录 (FR-02)
**描述：** 允许已注册用户通过凭证验证身份，进入系统。
**优先级：** 高

**用户故事：**
*   作为一个已注册用户，我希望使用邮箱/手机号和密码登录系统。
*   作为一个已注册用户，我希望在登录时可以选择“记住我”，以便在一定期限内免登录。
*   作为一个已注册用户，我希望在连续多次输错密码后，账户被临时锁定以增强安全性。

**验收标准：**
*   AC-02.1：登录界面应允许用户输入邮箱/手机号作为账号，并输入密码。
*   AC-02.2：系统应验证账号是否存在、密码是否正确、账户是否已激活且未被禁用。
*   AC-02.3：验证成功后，系统应创建用户会话（如生成JWT），并跳转至用户上次访问的页面或默认首页。
*   AC-02.4：提供“记住我”复选框。若勾选，会话有效期应延长（如7天）；否则，会话在浏览器关闭后失效。
*   AC-02.5：同一账号连续5次输入错误密码后，该账号应被锁定15分钟，并给出明确提示。
*   AC-02.6：登录成功后，应在界面显眼位置显示当前登录的用户名或昵称。

### 3.3 密码管理 (FR-03)
**描述：** 允许用户修改密码或在忘记密码时重置密码。
**优先级：** 中

**用户故事：**
*   作为一个已登录用户，我希望能够修改我的登录密码。
*   作为一个忘记密码的用户，我希望通过注册邮箱或手机号重置我的密码。

**验收标准：**
*   AC-03.1：在用户个人设置或安全中心中，应提供“修改密码”功能。
*   AC-03.2：修改密码时，用户必须提供原密码、新密码并确认新密码。原密码必须验证正确。
*   AC-03.3：密码修改成功后，当前所有其他设备的会话应失效，需要重新登录。
*   AC-03.4：登录页面应提供“忘记密码”链接。
*   AC-03.5：用户点击“忘记密码”后，需输入注册的邮箱或手机号。
*   AC-03.6：系统向该邮箱/手机号发送包含验证码或重置链接的信息。
*   AC-03.7：用户通过验证后，可设置新密码。新密码生效后，旧密码立即失效。

### 3.4 用户登出 (FR-04)
**描述：** 允许已登录用户安全地终止当前会话。
**优先级：** 低

**用户故事：**
*   作为一个已登录用户，我希望能够安全地退出登录，以保护我的账户隐私。

**验收标准：**
*   AC-04.1：用户界面中应提供明显的“退出”或“登出”按钮或链接。
*   AC-04.2：用户点击登出后，服务器端应立即使当前会话令牌失效。
*   AC-04.3：登出后，客户端应清除本地存储的会话信息（如Token），并重定向至登录页面或首页。

### 3.5 第三方账号登录 (FR-05)
**描述：** 允许用户使用第三方平台（如微信、GitHub）的账号快速登录或绑定现有账户。
**优先级：** 中

**用户故事：**
*   作为一个新用户，我希望使用我的微信账号快速注册并登录，避免繁琐的填写过程。
*   作为一个已有系统账户的用户，我希望将我的GitHub账号绑定到现有账户上，以便未来使用GitHub登录。

**验收标准：**
*   AC-05.1：登录/注册页面应显示支持的第三方登录图标（如微信、GitHub）。
*   AC-05.2：用户点击第三方图标后，应跳转至对应平台的授权页面。
*   AC-05.3：用户授权成功后，系统应接收第三方平台返回的用户唯一标识（如OpenID）。
*   AC-05.4：若此标识未绑定任何系统账户，则视为新用户，系统应引导用户补充必要信息（如设置用户名）后完成自动注册与登录。
*   AC-05.5：若此标识已绑定系统账户，则直接使用绑定的系统账户完成登录。
*   AC-05.6：在用户账户设置中，应提供“绑定第三方账号”和“解绑第三方账号”的功能。

## 4. 约束条件

*   **技术约束：** 认证令牌必须采用JWT标准，后端API必须为无状态设计。
*   **安全约束：** 所有密码在存储前必须进行不可逆的哈希加盐处理。传输层必须使用HTTPS。
*   **合规约束：** 用户数据的收集、存储和处理需符合《个人信息保护法》等相关法律法规。
*   **第三方约束：** 第三方登录功能受限于对应平台（微信、GitHub）的API政策与调用限额。
