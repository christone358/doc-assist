## ADDED Requirements

### Requirement: 文档编写Skill的标准规范
文档编写Skill应该遵循统一的标准，以支持Agent进行文档编写工作。每个文档编写Skill都应该：

#### Scenario: 文档编写Skill的核心职责
- **WHEN** 一个文档编写Skill被开发和注册
- **THEN** 该Skill应该具备以下核心能力：
  1. **新增编写** - 从零开始编写文档，基于用户需求和项目事实信息
  2. **精准修改** - 在已有文档版本基础上进行修改，改进文档内容
  3. **文档理解** - 理解并遵循该文档类型的规范和最佳实践
  4. **上下文利用** - 充分利用项目事实信息和用户提供的背景信息

#### Scenario: Skill的输入参数标准
- **WHEN** Agent调用文档编写Skill时
- **THEN** Skill应该接受以下标准输入参数：
  - `operation_type`: 操作类型（"create" 新增 或 "modify" 修改）
  - `document_type`: 文档类型（由Skill的类型定义）
  - `user_requirement`: 用户的自然语言需求描述
  - `project_context`: 项目事实信息（清单层、核心信息层等）
  - `existing_content`: 如果是修改操作，提供已有文档内容
  - `target_section`: 修改操作时，指定要修改的文档部分（可选）
  - `modification_intent`: 修改操作时，说明修改意图

#### Scenario: Skill的输出标准
- **WHEN** 文档编写Skill执行完成后
- **THEN** Skill应该返回以下标准输出：
  - `status`: 执行状态（"success" 或 "failure"）
  - `generated_content`: 生成或修改后的文档内容
  - `modification_details`: 如果是修改操作，说明修改了哪些部分（可选）
  - `references`: 文档中引用的项目事实信息列表（用于溯源）
  - `suggestions`: Agent向用户提供的建议或需要澄清的问题（可选）
  - `errors`: 如果执行失败，提供详细的错误信息

### Requirement: 文档编写Skill应该遵循的设计原则
文档编写Skill的开发应该遵循以下原则，确保文档质量和一致性。

#### Scenario: 内容准确性
- **WHEN** 文档编写Skill生成或修改文档时
- **THEN** Skill应该：
  1. 准确引用项目事实信息（不能臆造或错误引用）
  2. 标注信息的来源（如"根据接口清单..."、"基于用例描述..."）
  3. 如果事实信息不足，主动告知用户而不是猜测

#### Scenario: 文档结构一致性
- **WHEN** Skill定义所属文档类型的结构时
- **THEN** Skill应该：
  1. 在skill.md中清晰定义该文档类型的标准结构（章节、小节、内容要点）
  2. 新增和修改操作都应该遵循这个结构
  3. 结构应该是合理的、行业标准的

#### Scenario: 修改的精准性
- **WHEN** 用户请求修改文档的特定部分时
- **THEN** Skill应该：
  1. 准确定位用户指示的修改位置
  2. 仅修改指定部分，保持其他内容不变
  3. 确保修改后的文档结构和逻辑完整

#### Scenario: 上下文理解
- **WHEN** Skill在生成文档时
- **THEN** Skill应该：
  1. 充分利用项目事实信息
  2. 参考同类型的已有文档（如有）
  3. 理解文档的使用场景和读者需求
  4. 确保文档风格和项目一致

### Requirement: 文档编写Skill的开发指南（在skill.md中说明）
每个文档编写Skill的skill.md应该包含足够的信息指导Agent和用户如何使用该Skill。

#### Scenario: skill.md应包含的文档类型信息
- **WHEN** 用户或Agent查看一个文档编写Skill的描述时
- **THEN** skill.md应该包含：
  1. **文档类型说明** - 该Skill负责的文档类型是什么
  2. **文档结构定义** - 生成的文档应该包含哪些章节和内容
  3. **使用场景** - 这种文档的使用场景和目的
  4. **内容示例** - 一个简单的文档示例，展示预期的格式和风格
  5. **参考资料** - 行业标准、模板、最佳实践的参考链接

#### Scenario: skill.md应包含的输入要求说明
- **WHEN** Agent需要调用该Skill时
- **THEN** skill.md应该说明：
  1. **必需的用户信息** - 用户必须提供哪些信息
  2. **可选的补充信息** - 用户可以提供哪些补充信息来改进文档质量
  3. **项目事实信息需求** - 该Skill依赖的项目事实信息是什么（如需要哪些模块信息、用例等）
  4. **修改指导** - 用户在修改时应该如何表达修改意图，以便Skill准确理解

#### Scenario: skill.md应包含的能力和限制说明
- **WHEN** 用户或Agent评估Skill是否适合某个任务时
- **THEN** skill.md应该说明：
  1. **能力范围** - 该Skill能够处理的各种情况
  2. **限制** - Skill无法处理的情况或依赖的外部条件
  3. **最佳实践** - 如何最有效地使用该Skill获得最好的结果

### Requirement: 文档编写Skill支持多轮对话迭代
文档编写Skill应该支持在多轮对话中进行迭代改进，而不仅仅是一次性生成。

#### Scenario: 接受用户反馈和改进
- **WHEN** 用户对生成的文档提出反馈（如"这部分需要更详细"、"这里有误"）
- **THEN** Skill应该：
  1. 理解用户的反馈
  2. 基于反馈对文档进行改进
  3. 生成改进后的版本并展示修改差异

#### Scenario: 渐进式完善
- **WHEN** 用户通过多轮对话逐步完善文档时
- **THEN** Skill应该：
  1. 在每一轮中基于之前的版本进行改进
  2. 保持文档的一致性和完整性
  3. 记住用户的偏好和反馈

### Requirement: 文档编写Skill的交互模式
文档编写Skill应该在与Agent和LLM的交互中表现出适当的主动性。

#### Scenario: 澄清不明确的需求
- **WHEN** Skill接收到不明确或不足的需求
- **THEN** Skill应该：
  1. 向Agent（进而向用户）提出澄清问题
  2. 提供多个理解可能性供用户选择
  3. 询问用户关于文档的预期用途、读者等

#### Scenario: 提出改进建议
- **WHEN** Skill分析用户需求和项目事实信息后
- **THEN** Skill可以主动：
  1. 提出文档结构或内容的改进建议
  2. 指出可能遗漏的重要内容
  3. 建议参考相关的项目事实信息

### Requirement: 文档编写Skill的质量保证
文档编写Skill应该对生成的文档质量负责。

#### Scenario: 内容验证
- **WHEN** Skill生成文档内容时
- **WHEN** Skill应该：
  1. 验证内容的准确性（与事实信息一致）
  2. 验证格式和结构的合理性
  3. 检查是否存在明显的语义或逻辑错误

#### Scenario: 版本追踪
- **WHEN** 文档经过多次修改
- **THEN** Skill应该能够：
  1. 追踪文档的演变历史
  2. 理解不同版本之间的差异
  3. 支持用户回到之前的版本
