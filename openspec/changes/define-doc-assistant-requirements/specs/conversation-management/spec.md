## ADDED Requirements

### Requirement: 对话记录的持久化和管理
系统应该能够保存每次用户编写为一个对话记录，并支持管理多个对话记录。

#### Scenario: 创建新对话
- **WHEN** 用户开始新的文档编写任务
- **THEN** 系统应该：
  1. 创建一个新的对话记录
  2. 记录对话的创建时间
  3. 为对话分配唯一的ID
  4. 允许用户为对话命名（如"API文档编写"、"需求文档v2"）

#### Scenario: 对话数据结构
- **WHEN** 系统保存对话时
- **THEN** 对话记录应包含：
  - `conversation_id`: 唯一标识符
  - `name`: 对话名称（用户自定义）
  - `description`: 对话描述（可选）
  - `created_at`: 创建时间
  - `updated_at`: 最后更新时间
  - `status`: 对话状态（进行中/已完成）
  - `document_type`: 本次对话的主要文档类型（可选，用户指定或自动识别）
  - `conversation_rounds`: 对话轮次（包含所有对话内容）

#### Scenario: 对话列表
- **WHEN** 用户查看对话列表时
- **THEN** 系统应该：
  1. 显示所有对话记录（按创建时间排序）
  2. 对每个对话显示：名称、创建时间、最后更新时间、文档类型、状态
  3. 支持搜索和筛选（按名称、日期、类型等）
  4. 支持排序（按名称、时间等）

#### Scenario: 对话详情查看
- **WHEN** 用户点击某个对话
- **THEN** 系统应该：
  1. 显示对话的完整信息
  2. 显示对话的所有轮次（用户输入和Agent响应）
  3. 显示在该对话中生成的所有文档
  4. 显示对话的时间线

#### Scenario: 对话的暂存和继续
- **WHEN** 用户在对话过程中离开或关闭应用
- **THEN** 系统应该：
  1. 自动保存当前对话状态
  2. 用户可以在任何时间继续该对话（对话状态从"进行中"恢复）
  3. 继续对话时，对话历史完整显示

### Requirement: 对话过程的详细记录
系统应该记录对话的所有细节，便于后续的回查和分析。

#### Scenario: 对话轮次记录
- **WHEN** 用户和Agent进行交互时
- **THEN** 系统应该记录每一轮对话：
  - `round_id`: 轮次编号（1, 2, 3...）
  - `timestamp`: 对话发生的时间
  - `user_input`: 用户的输入内容
  - `agent_response`: Agent的响应内容
  - `agent_reasoning`: Agent的推理过程或思考摘要（如有）
  - `skill_invoked`: 调用的Skill及其参数
  - `llm_info`: LLM调用信息（模型、参数、令牌数等）
  - `documents_generated`: 本轮生成的文档（及版本）
  - `state_snapshot`: 对话状态快照（当前已确认的需求、已生成的文档等）

#### Scenario: Skill调用记录
- **WHEN** Agent调用一个Skill时
- **THEN** 系统应该记录：
  - Skill名称和版本
  - 调用参数
  - Skill的执行时间
  - Skill的返回结果
  - Skill的执行状态（成功/失败/部分成功）
  - 如果失败，记录错误信息

#### Scenario: LLM调用记录
- **WHEN** Agent调用LLM时
- **THEN** 系统应该记录：
  - LLM模型名称
  - 使用的提示词（或提示词摘要）
  - LLM的回复内容
  - 令牌使用统计（输入令牌、输出令牌）
  - LLM调用耗时
  - 如果启用深度思考，记录思考内容

#### Scenario: 文档变更追踪
- **WHEN** 对话过程中生成或修改文档时
- **THEN** 系统应该记录：
  - 文档的ID和类型
  - 生成/修改的时间
  - 是新增还是修改（及修改的版本号）
  - 生成该文档的对话轮次
  - 对应的Skill和LLM参数

### Requirement: 对话与文档的关联
系统应该清晰地显示对话与文档的关联关系，便于用户追踪文档的来源。

#### Scenario: 对话中的文档列表
- **WHEN** 用户查看一个对话
- **THEN** 系统应该显示该对话中生成的所有文档：
  - 文档名称、类型、版本
  - 文档的生成时间
  - 生成文档的轮次
  - 文档的最新版本和所有历史版本
  - 文档在输出目录中的位置

#### Scenario: 文档的版本链追踪
- **WHEN** 用户查看一个文档
- **THEN** 系统应该显示：
  - 该文档的所有版本（按时间顺序）
  - 每个版本对应的对话ID和轮次
  - 每个版本之间的修改（Diff）
  - 修改的原因或用户的反馈

#### Scenario: 对话回放
- **WHEN** 用户想要回顾对话的演进过程
- **THEN** 系统应该支持：
  1. 逐轮回放对话（可控制速度）
  2. 在每一轮显示该轮生成的文档
  3. 显示该轮生成文档的版本号
  4. 支持在任意轮次"冻结"对话进度，查看该时点的文档状态

### Requirement: 文档输出目录管理
系统应该提供灵活的文档输出目录管理，组织生成的文档。

#### Scenario: 目录结构配置
- **WHEN** 系统管理员配置文档输出目录
- **THEN** 系统应该支持：
  1. 设置输出根目录（全局配置）
  2. 支持按对话组织（每个对话一个目录）
  3. 支持在对话目录下按文档类型分类
  4. 支持按日期组织（年/月/日）
  5. 支持自定义目录命名规则

#### Scenario: 默认目录结构
- **WHEN** 系统初始化文档输出目录
- **THEN** 默认结构应该为：
  ```
  docs/
    conversations/
      [conversation_id]/
        documents/
          requirements/
            doc-name_YYYY-MM-DD_vX.Y.Z.md
          design/
            doc-name_YYYY-MM-DD_vX.Y.Z.md
          test/
            doc-name_YYYY-MM-DD_vX.Y.Z.md
        conversation_log.json  # 对话详细记录
        conversation_summary.md # 对话总结
  ```

#### Scenario: 文档输出配置
- **WHEN** 用户或管理员需要配置输出目录
- **THEN** 系统应该支持：
  1. 配置输出目录的根路径
  2. 配置目录的命名规则（可使用变量如{conversation_id}、{date}、{doc_type}）
  3. 配置是否启用版本管理（按版本号创建子目录或文件名包含版本）
  4. 保存配置并立即生效

#### Scenario: 文档的自动导出
- **WHEN** Skill生成或修改文档时
- **THEN** 系统应该：
  1. 自动将文档保存到输出目录（按配置的目录结构）
  2. 生成相应的版本号和时间戳
  3. 记录文件的输出路径
  4. 更新对话的文档列表
