# 4. 脆弱性管理模块说明

## 4.1 模块概述

脆弱性管理模块是业务保障管理系统的重要组成部分，面向资产管理员，提供对资产安全漏洞（脆弱性）的全生命周期管理能力。该模块覆盖脆弱性的发现、扫描、分析、修复跟踪与验证闭环，旨在帮助管理员高效识别安全风险，提升漏洞修复率，保障业务资产安全。

**核心功能**：
- **脆弱性总览**：集中展示漏洞整体态势与核心风险指标。
- **脆弱性检测**：配置扫描任务、管理扫描引擎、导入漏洞数据。
- **脆弱性列表**：多维度查询、统计与查看漏洞清单。
- **脆弱性详情与处置**：查看漏洞详情、下发修复任务、标记状态、触发验证扫描。

**目标用户**：资产管理员、安全运维人员。

## 4.2 功能说明

### 4.2.1 脆弱性总览

**功能描述**：
提供脆弱性风险全局视图，通过可视化图表展示核心安全指标，支持管理员快速把握整体风险态势与趋势。

**操作指南**：
1. 进入“脆弱性管理”模块，默认展示“脆弱性总览”页面。
2. 页面主要展示以下核心指标卡片与图表（待确认界面具体布局）：
   - **漏洞总量**：当前系统中所有未关闭的漏洞数量。
   - **等级分布**：按高危、中危、低危、信息级别统计的漏洞数量及占比饼图/柱状图。
   - **TOP风险资产**：列出受漏洞影响最严重的前N个资产（如业务系统、服务器）。
   - **修复率**：已修复漏洞数占总发现漏洞数的百分比。
   - **平均修复时间**：从漏洞发现到修复完成的平均耗时。
3. 用户可通过时间筛选器（如近7天、近30天、自定义时间范围）查看不同时间段的风险趋势变化。

### 4.2.2 脆弱性检测

本子模块负责漏洞的发现与数据接入，包括扫描任务管理、扫描引擎集成与手动数据导入。

#### 4.2.2.1 扫描任务管理

**功能描述**：
创建、配置、调度和执行自动化脆弱性扫描任务，对指定资产范围进行定期或一次性的漏洞扫描。

**操作指南**：
1. **创建扫描任务**：
   a. 在“脆弱性检测”菜单下，点击“扫描任务管理”。
   b. 点击“新建任务”按钮。
   c. 在弹窗中填写任务信息：
      - **任务名称**：输入易于识别的任务名称。
      - **扫描目标**：选择扫描的资产范围（如特定IP段、业务系统、资产标签）。待确认具体选择方式。
      - **扫描策略**：选择预定义的扫描策略（如全面扫描、快速扫描）。待补充策略配置入口说明。
      - **扫描引擎**：选择执行扫描的引擎设备。需先完成“脆弱性检测设备管理”中的引擎接入。
      - **调度方式**：选择“立即执行”或“周期执行”（如每天、每周）。
      - **高级设置**：可配置扫描强度、超时时间等（待补充具体参数）。
   d. 点击“确定”保存并启动任务（若选择立即执行）。

2. **管理扫描任务**：
   - **任务列表**：查看所有扫描任务，列表显示任务名称、状态（等待中、进行中、已完成、失败）、上次执行时间、下次执行时间等。
   - **操作**：支持对任务执行“启动”、“暂停”、“编辑”、“删除”、“查看日志”等操作。

#### 4.2.2.2 脆弱性检测设备管理

**功能描述**：
对接和管理第三方漏洞扫描引擎或设备，确保扫描任务能够被正确调度和执行。

**操作指南**：
1. **添加扫描引擎**：
   a. 在“脆弱性检测”菜单下，点击“检测设备管理”。
   b. 点击“添加设备”按钮。
   c. 填写引擎信息：
      - **设备名称**：自定义名称。
      - **设备类型**：选择引擎品牌/类型（如Nessus, OpenVAS等）。待确认支持的具体类型。
      - **连接地址**：输入引擎的API访问地址（URL）。
      - **认证信息**：输入访问引擎所需的用户名、密码或API Key。
   d. 点击“测试连接”验证配置是否正确。
   e. 点击“保存”完成添加。

2. **管理设备**：
   - 在设备列表中，可查看已接入引擎的状态（在线、离线）、版本等信息。
   - 支持对设备进行“编辑”、“删除”、“同步资产”等操作。

#### 4.2.2.3 脆弱性导入

**功能描述**：
支持通过上传标准化报告文件（如XML, CSV格式）的方式，手动导入由其他扫描工具发现的漏洞数据。

**操作指南**：
1. 在“脆弱性检测”菜单下，点击“脆弱性导入”。
2. 点击“导入文件”按钮。
3. 选择本地的漏洞报告文件。系统支持（待补充具体支持的文件格式，如Nessus .nessus, OpenVAS .xml）。
4. 系统解析文件后，会显示预览信息，包括将要导入的漏洞数量、受影响资产数量等。
5. 确认无误后，点击“开始导入”。系统将解析数据并与现有资产进行关联，新增或更新漏洞记录。
6. 导入完成后，可在“脆弱性列表”中查看导入的漏洞。

### 4.2.3 脆弱性列表

**功能描述**：
提供多维度、可筛选的漏洞清单视图，支持按业务系统、责任人等视角查看漏洞，并具备统计功能。

**操作指南**：
1. **视图切换与统计**：
   - 进入“脆弱性列表”页面，顶部可能提供视图切换选项卡，如“全部漏洞”、“按业务系统”、“按责任人”。
   - 页面顶部或侧边栏会显示当前列表的统计摘要，如各风险等级漏洞数量。

2. **检索漏洞**：
   - 使用页面提供的搜索框和筛选条件进行精确查询。筛选条件可能包括：
     - **漏洞名称/编号**：输入CVE编号或关键字。
     - **风险等级**：下拉选择高危、中危、低危等。
     - **资产/IP**：输入受影响的资产名称或IP地址。
     - **业务系统**：下拉选择特定业务系统。
     - **责任人**：下拉选择资产责任人。
     - **状态**：选择“待处理”、“修复中”、“已修复”、“误报”、“已忽略”等。
     - **发现时间**：选择时间范围。
   - 点击“搜索”按钮应用筛选条件。

3. **查看列表与操作**：
   - 列表展示每条漏洞的核心信息：漏洞名称、CVE编号、风险等级、受影响资产/业务系统、责任人、发现时间、当前状态。
   - 点击列表中的“详情”按钮或漏洞名称链接，可跳转至“脆弱性详情”页面。
   - 在列表行末，可能提供快捷操作，如“下发任务”、“标记状态”。

### 4.2.4 脆弱性详情与处置

**功能描述**：
展示单个漏洞的详细信息，并提供完整的处置工作流，包括下发修复任务、标记状态和触发修复验证。

**操作指南**：
1. **查看漏洞详情**：
   - 从“脆弱性列表”点击进入“脆弱性详情”页面。
   - 页面分区域展示以下信息：
     - **基础信息**：漏洞名称、CVE编号、CNNVD编号、公开时间、CVSS评分/向量、风险等级。
     - **漏洞描述**：详细的技术描述、可能造成的危害。
     - **修复方案**：官方或社区提供的修补建议、补丁链接、临时缓解措施。
     - **受影响资产**：列表展示受此漏洞影响的所有资产，包括资产名称、IP、所属业务系统、责任人。
     - **处置历史**：记录该漏洞所有的状态变更、任务下发、备注信息。

2. **下发处置任务**：
   a. 在详情页找到“处置”区域，点击“下发处置任务”按钮。
   b. 系统将自动生成一个整改工单（或协同任务），并关联该漏洞及所有受影响资产的责任人。
   c. 在弹出的任务确认窗口中，可补充任务要求、截止时间等说明（待确认具体表单字段）。
   d. 点击“确认下发”，任务将推送至相关责任人的待办事项中（如协同工作中心）。

3. **标记漏洞状态**：
   - 对于无需修复或已处理的漏洞，管理员可直接在详情页进行状态标记：
     - **标记为误报**：确认该漏洞在当前资产环境中不存在或扫描结果为误报。需填写误报理由。
     - **标记为已修复**：确认漏洞已通过其他方式修复。需填写修复说明，并可上传证明文件。
     - **忽略**：已知晓风险但决定暂不处理。需填写忽略原因及有效期。

4. **修复验证**：
   - 对于标记为“已修复”的漏洞，可进行验证以确保修复有效。
   a. 在详情页点击“修复验证”按钮。
   b. 系统将自动针对受影响资产发起一次针对性的验证扫描（通常为快速扫描）。
   c. 验证扫描完成后，系统会自动更新漏洞状态：
     - 若未扫描出该漏洞，则状态自动变更为“已验证修复”，实现闭环。
     - 若仍扫描出该漏洞，则状态回退为“待处理”，并通知相关人员。

## 4.3 常见问题与处理

- **Q：扫描任务一直处于“进行中”状态，如何处理？**
  A：首先检查所选扫描引擎设备状态是否为“在线”。然后通过“查看日志”功能检查任务执行日志。常见原因包括网络不通、引擎负载过高、扫描目标不可达。可尝试重启任务或联系引擎管理员。

- **Q：导入漏洞报告后，部分漏洞未关联到资产？**
  A：这是因为报告中提供的资产信息（如IP）在系统的资产库中不存在或未匹配。请先确保相关资产已录入“资产管理”模块，或检查报告中的IP格式是否标准。

- **Q：下发处置任务后，责任人反馈未收到？**
  A：请确认系统“协同工作中心”模块运行正常。同时，在“任务执行记录”中可查询该任务的详细状态和流转记录。

- **Q：修复验证扫描失败？**
  A：验证扫描依赖于原扫描引擎。请检查引擎状态及网络连接。验证扫描通常只针对特定漏洞，请确保验证时资产IP和端口可访问。

## 4.4 风险提示

1. **扫描影响**：全端口或深度扫描可能对目标系统的性能和稳定性造成影响，请在业务低峰期执行，并提前通知相关业务负责人。
2. **漏洞修复**：修复高危漏洞前，务必在测试环境验证修复方案，避免直接在生产环境操作导致业务中断。
3. **权限控制**：脆弱性数据属于敏感信息，应严格按照岗位职责分配模块的查看与操作权限。
4. **数据时效**：漏洞库需定期更新，以确保扫描引擎能识别最新漏洞。请关注扫描引擎的插件更新情况。
