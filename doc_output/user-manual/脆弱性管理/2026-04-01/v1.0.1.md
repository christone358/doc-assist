# 4. 脆弱性管理模块说明

## 4.1 模块概述

脆弱性管理模块是业务保障管理系统资产脆弱性管理子系统的核心组成部分，面向资产管理员与安全运维人员，提供对资产安全漏洞（脆弱性）的全生命周期管理能力。该模块覆盖脆弱性的发现、评估、修复跟踪与验证闭环，旨在帮助用户高效识别安全风险，提升漏洞修复率，保障业务资产安全。

**核心功能**：
- **脆弱性扫描管理**：配置和管理自动化扫描任务，接入扫描设备，导入漏洞数据。
- **脆弱性评估与分级**：基于CVSS等标准对漏洞进行风险评级与展示。
- **修复跟踪与验证**：下发修复任务、跟踪处理进度、触发验证扫描以实现闭环。
- **报告生成**：提供多维度漏洞统计与报告导出功能。

**目标用户**：系统管理员、安全运维人员、资产管理员。

## 4.2 功能说明

### 4.2.1 脆弱性扫描管理

本子模块负责漏洞的自动化发现与数据接入，包括扫描任务管理、扫描设备管理及手动数据导入。

#### 4.2.1.1 扫描任务管理

**功能描述**：
创建、配置、调度和执行自动化脆弱性扫描任务，对指定的资产范围进行定期或一次性的漏洞扫描。

**操作指南**：
1. **创建扫描任务**：
   a. 在“脆弱性管理”主菜单下，进入“扫描任务管理”页面。
   b. 点击“新建任务”按钮。
   c. 在弹窗中填写任务信息：
      - **任务名称**：输入易于识别的任务名称。
      - **扫描目标**：通过资产树、IP段或资产标签选择扫描范围。待确认具体选择控件。
      - **扫描策略**：从下拉列表中选择预定义的扫描策略（如全面扫描、快速扫描）。待补充策略库管理入口。
      - **扫描引擎**：从已接入的设备列表中选择执行扫描的引擎。
      - **调度方式**：选择“立即执行”或“周期执行”（支持按小时、天、周设置）。
      - **高级设置**：可配置扫描超时时间、并发线程数等参数（待补充具体参数列表）。
   d. 点击“确定”保存任务。若选择“立即执行”，任务将进入执行队列。

2. **管理扫描任务**：
   - **任务列表**：查看所有任务，列表显示任务名称、状态（等待中、扫描中、已完成、失败、已停止）、上次执行时间、下次执行时间等。
   - **任务操作**：
     - **启动/停止**：对处于“等待中”或“已停止”状态的任务执行“启动”；对“扫描中”的任务执行“停止”。
     - **编辑**：修改未执行或已停止的任务配置。
     - **删除**：删除任务记录。
     - **查看报告**：对于已完成的任务，可查看本次扫描发现的漏洞摘要报告。
     - **执行日志**：点击“日志”查看任务执行的详细过程与错误信息。

#### 4.2.1.2 脆弱性检测设备管理

**功能描述**：
对接和管理第三方漏洞扫描引擎或设备，确保扫描任务能够被正确调度和执行。

**操作指南**：
1. **添加扫描设备**：
   a. 在“脆弱性管理”主菜单下，进入“检测设备管理”页面。
   b. 点击“添加设备”按钮。
   c. 填写设备连接信息：
      - **设备名称**：自定义标识名称。
      - **设备类型**：选择引擎品牌/类型（如Nessus, OpenVAS, 奇安信等）。待确认支持的具体类型列表。
      - **连接地址**：输入引擎的API访问地址（URL）。
      - **认证方式**：选择“用户名/密码”或“API Key”，并输入对应凭证。
   d. 点击“测试连接”按钮，验证网络连通性与认证信息是否正确。
   e. 连接测试通过后，点击“保存”完成设备添加。

2. **管理设备**：
   - 在设备列表中，可查看所有已接入设备的状态（在线、离线）、版本、最后心跳时间等信息。
   - 支持操作：
     - **编辑**：修改设备连接信息。
     - **删除**：移除设备。若该设备有关联的扫描任务，需先解除关联。
     - **同步资产**：手动触发从该扫描引擎同步其管理的资产列表至本系统。

#### 4.2.1.3 脆弱性导入

**功能描述**：
支持通过上传标准化报告文件的方式，手动导入由其他扫描工具发现的漏洞数据，实现多源漏洞数据的统一管理。

**操作指南**：
1. 在“脆弱性管理”主菜单下，进入“脆弱性导入”页面。
2. 点击“导入文件”按钮。
3. 选择本地的漏洞报告文件。系统支持常见扫描工具的报告格式（待补充具体支持的文件格式，如 `.nessus`, `.xml`, `.csv`）。
4. 系统解析文件后，会在页面显示预览信息，包括：文件中的漏洞总数、受影响资产数、以及可能无法匹配到现有资产的条目列表。
5. 确认无误后，点击“开始导入”。系统将解析数据，并与资产库进行匹配，新增或更新漏洞记录。
6. 导入完成后，页面提示导入成功/失败数量。用户可前往“脆弱性列表”查看导入的漏洞详情。

### 4.2.2 脆弱性评估与分级

**功能描述**：
系统依据通用漏洞评分系统（CVSS）标准对导入或扫描发现的漏洞进行自动评分与风险等级划分，并提供多维度视图进行统计与展示。

**操作指南**：
1. **查看风险总览**：
   - 进入“脆弱性管理”模块首页或“风险总览”页面。
   - 页面通过指标卡片和图表展示全局风险态势，包括：
     - **实时漏洞总数**（按状态筛选）。
     - **风险等级分布**：以饼图或柱状图展示高危、中危、低危、信息级别漏洞的数量及占比。
     - **TOP风险资产**：列表显示受漏洞影响最严重的前N个资产（业务系统或服务器）。
     - **近期趋势**：折线图展示近7天、30天新增漏洞数量变化趋势。

2. **多维度列表与筛选**：
   - 进入“脆弱性列表”页面，默认以表格形式展示所有漏洞。
   - **视图切换**：页面提供视图切换标签，如“全部漏洞”、“按业务系统视图”、“按责任人视图”，从不同维度聚合展示漏洞。
   - **综合检索**：利用页面顶部的搜索框与筛选器进行精确查询，筛选条件包括：
     - **漏洞标识**：CVE编号、CNNVD编号或漏洞名称关键词。
     - **风险等级**：下拉选择高危、中危、低危、信息。
     - **CVSS评分范围**：输入最小值和最大值。
     - **受影响资产**：输入资产名称、IP地址或选择资产组。
     - **所属业务系统**：从下拉列表中选择。
     - **责任人**：从下拉列表中选择资产责任人。
     - **漏洞状态**：选择待处理、修复中、已修复、误报、已忽略等。
     - **发现时间**：选择日期范围。
   - 点击“搜索”应用条件，点击“重置”清空筛选。

3. **评估结果应用**：
   - 列表中的每条漏洞均明确标注其CVSS评分（如9.8）和对应的风险等级（颜色标识）。
   - 用户可根据评分与等级，快速识别需要优先处理的高危漏洞。

### 4.2.3 修复跟踪与验证

**功能描述**：
提供从漏洞处置任务下发、状态跟踪到修复验证的完整闭环工作流，确保每个漏洞得到有效处理。

**操作指南**：
1. **查看漏洞详情**：
   - 在“脆弱性列表”中，点击任意漏洞名称或“详情”按钮，进入“脆弱性详情”页面。
   - 页面分区域展示完整信息：
     - **漏洞概要**：名称、CVE/CNNVD编号、公开时间、CVSS评分/向量、风险等级、当前状态。
     - **技术详情**：漏洞描述、受影响组件、攻击路径、潜在影响。
     - **修复建议**：官方补丁链接、升级指南、临时缓解措施。
     - **受影响资产列表**：展示所有受此漏洞影响的资产，包括资产名称、IP、所属业务系统、责任人及该资产上此漏洞的单独状态。
     - **处置轨迹**：按时间倒序列出所有状态变更、任务下发、备注记录。

2. **下发处置任务**：
   a. 在详情页的“处置”区域，点击“下发处置任务”按钮。
   b. 系统将自动生成一张整改工单，并关联此漏洞及所有受影响资产的责任人。
   c. 在弹出的任务确认窗口中，可补充以下信息（待确认具体表单）：
      - **任务标题**：自动生成，可编辑。
      - **处理要求**：详细描述修复步骤或要求。
      - **紧急程度**：选择高、中、低。
      - **期望完成时间**：设置截止日期。
   d. 点击“确认下发”，工单将推送至相关责任人的待办列表（通常集成至协同工作中心）。漏洞状态自动变更为“修复中”。

3. **标记漏洞状态**：
   - 对于无需通过工单流程处理的漏洞，管理员可直接在详情页进行快速状态标记：
     - **标记为误报**：确认该漏洞为误报。需在弹出的窗口中填写“误报原因”。
     - **标记为已修复**：确认漏洞已通过其他途径修复。需填写“修复说明”，并可上传修复证明（如截图、命令执行结果）。
     - **忽略**：已知风险但决定暂不处理。需填写“忽略原因”并设置“忽略有效期”。
   - 状态变更后，系统会记录操作人、时间及原因。

4. **触发修复验证**：
   - 对于状态为“已修复”的漏洞，可触发验证扫描以确认修复有效性。
   a. 在详情页点击“修复验证”按钮。
   b. 系统提示将发起一次针对性的验证扫描（通常仅检查该漏洞是否存在）。
   c. 确认后，系统自动向原扫描引擎提交验证任务。
   d. 验证完成后，系统自动更新漏洞状态：
     - 验证通过（未扫出）：状态更新为“已验证修复”，处置闭环。
     - 验证未通过（仍存在）：状态回退为“待处理”，并生成通知提醒相关人员。

### 4.2.4 报告生成

**功能描述**：
根据用户需求，生成不同维度、不同时间范围的脆弱性统计分析报告，并支持导出为常用格式。

**操作指南**：
1. **进入报告功能**：
   - 在“脆弱性管理”主菜单下，进入“报告中心”或“报告生成”页面。待确认具体菜单路径。

2. **生成报告**：
   a. 点击“新建报告”按钮。
   b. 配置报告参数：
      - **报告名称**：自定义报告名称。
      - **报告类型**：选择报告模板，如“漏洞风险汇总报告”、“资产漏洞明细报告”、“修复效率分析报告”。待补充具体报告模板列表。
      - **时间范围**：选择报告覆盖的时间段（如本月、本季度、自定义起止日期）。
      - **筛选条件**：可叠加资产范围、业务系统、风险等级等筛选条件，使报告更聚焦。
      - **输出格式**：选择报告导出格式，如PDF、Word、Excel。
   c. 点击“生成预览”按钮，系统根据条件生成报告预览。
   d. 预览确认无误后，点击“导出报告”按钮，将报告文件下载至本地。

3. **查看历史报告**：
   - 在报告列表中可以查看已生成的历史报告记录，支持按报告名称、生成时间查询。
   - 对于已生成的报告，可执行“再次下载”、“删除”操作。

## 4.3 常见问题与处理

- **Q：新建的扫描任务始终无法启动？**
  A：请按以下步骤排查：1）检查所选“扫描引擎”设备状态是否为“在线”；2）检查“扫描目标”中的资产IP地址是否可达；3）查看任务“执行日志”获取具体错误信息。常见原因为引擎认证失败或网络策略限制。

- **Q：导入漏洞报告后，为何有些资产显示“未关联”？**
  A：这是因为报告中提供的资产标识（如IP、主机名）未在系统的资产库中找到完全匹配项。请前往“资产管理”模块确认资产已录入，或检查导入文件的资产信息格式是否正确。

- **Q：下发了处置任务，但责任人声称未收到通知？**
  A：首先，在漏洞详情页的“处置轨迹”中确认任务已成功下发。其次，确认系统集成的通知渠道（如站内信、邮件、即时通讯）配置正常。最后，可联系系统管理员检查协同工作中心的流程配置。

- **Q：点击“修复验证”后，长时间无结果？**
  A：验证扫描依赖原扫描引擎。请检查：1）该引擎设备是否在线；2）待验证的资产当前是否可被引擎访问（网络策略、主机状态）；3）通过引擎管理界面查看验证任务队列状态。

- **Q：报告生成速度很慢？**
  A：生成涉及大量历史数据统计的报告可能需要较长时间。建议：1）尝试缩小报告的时间范围；2）增加更具体的筛选条件以减少数据量；3）在系统业务低峰期执行生成操作。

## 4.4 风险提示

1. **扫描操作风险**：全端口扫描或深度检测可能对目标系统的性能和稳定性产生影响，甚至可能触发安全防护设备的告警。请在获得授权后，于业务低峰期执行，并提前通知相关业务负责人。
2. **漏洞修复风险**：修复高危漏洞，尤其是涉及系统补丁或配置变更的操作，必须在测试环境中充分验证，制定回滚方案，避免直接在生产环境实施导致业务中断。
3. **数据安全风险**：脆弱性数据详细揭示了资产的安全弱点，属于敏感信息。必须通过系统权限机制严格控制访问范围，仅对授权的安全运维人员开放，并禁止未加密的外发。
4. **漏洞库时效风险**：扫描引擎的漏洞检测能力依赖于其插件库的更新。为确保能发现最新漏洞，请定期关注并升级扫描引擎的漏洞插件，同时关注系统内置漏洞知识库的更新情况。
