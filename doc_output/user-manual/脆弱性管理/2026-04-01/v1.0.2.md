# 4. 软件操作指南

## 4.1 模块概述

脆弱性管理模块是业务保障管理系统资产脆弱性管理子系统的核心组成部分，面向资产管理员与安全管理员，提供对资产安全漏洞（脆弱性）的全生命周期管理能力。该模块覆盖脆弱性的发现、评估、修复跟踪与验证闭环，旨在帮助用户高效识别安全风险，提升漏洞修复率，保障业务资产安全。

**核心功能**：
- **脆弱性扫描与导入**：配置和管理自动化扫描任务，接入扫描设备，手动导入漏洞数据。
- **脆弱性评估与视图**：基于CVSS等标准对漏洞进行风险评级，并提供多维度视图进行统计与检索。
- **修复跟踪与验证**：下发修复任务、跟踪处理进度、触发验证扫描以实现闭环。

**目标用户**：安全管理员、资产管理员。

## 4.2 功能说明

### 4.2.1 脆弱性列表

本子模块提供脆弱性的集中展示、多维度统计与检索能力，支持用户从不同视角（如业务系统、责任人）查看和管理漏洞。

#### 4.2.1.1 脆弱性视图统计

**功能描述**：
在脆弱性列表页面或模块首页，通过可视化图表和指标卡片，全局展示当前漏洞风险态势，帮助用户快速掌握整体安全状况。

**操作指南**：
1. 进入“脆弱性管理”模块，默认展示首页或“脆弱性列表”页面。
2. 页面顶部或侧边栏区域将展示关键风险指标，通常包括：
   - **实时漏洞总数**：按状态（如待处理、修复中、已修复）分类统计的数量。
   - **风险等级分布**：以饼图或柱状图展示高危、中危、低危、信息级别漏洞的数量及占比。
   - **TOP风险资产**：列表显示受漏洞影响最严重的前N个资产（业务系统或服务器）。
   - **近期趋势**：折线图展示近7天、30天新增漏洞数量变化趋势。
3. 用户可通过点击图表中的特定区域（如某个风险等级区块）或“TOP风险资产”条目，快速跳转至对应的筛选后的脆弱性列表。

#### 4.2.1.2 脆弱性检索

**功能描述**：
提供强大的综合检索与筛选功能，帮助用户在海量漏洞数据中快速定位到关心的特定漏洞集合。

**操作指南**：
1. 在“脆弱性列表”页面顶部，找到搜索框与筛选器面板。
2. 使用以下一种或多种条件组合进行精确查询：
   - **漏洞标识**：输入CVE编号、CNNVD编号或漏洞名称关键词。
   - **风险等级**：从下拉列表中选择高危、中危、低危、信息。
   - **CVSS评分范围**：输入最小值和最大值以限定评分区间。
   - **受影响资产**：输入资产名称、IP地址进行模糊匹配，或从资产树中选择特定资产/资产组。
   - **所属业务系统**：从下拉列表中选择具体的业务系统。
   - **责任人**：从下拉列表中选择资产责任人。
   - **漏洞状态**：选择待处理、修复中、已修复、误报、已忽略等。
   - **发现时间**：通过日期选择器指定漏洞的发现时间范围。
3. 点击“搜索”或“查询”按钮应用所有筛选条件。
4. 列表将实时刷新，仅显示符合所有条件的漏洞记录。点击“重置”按钮可清空所有筛选条件，恢复默认视图。

#### 4.2.1.3 脆弱性列表

**功能描述**：
以表格形式清晰展示所有漏洞的概要信息，并支持切换不同视角（如业务系统视图、责任人视图）来聚合查看漏洞，便于不同角色的用户进行管理。

**操作指南**：
1. **查看默认列表**：
   - 进入“脆弱性列表”页面，默认以“全部漏洞”视图展示。
   - 列表通常包含以下关键字段：漏洞名称、CVE编号、风险等级（带颜色标识）、CVSS评分、受影响资产数、责任人、状态、发现时间。
   - 点击表头可对相应列进行升序/降序排序。

2. **切换视图**：
   - 页面提供视图切换标签，例如：
     - **“全部漏洞”**：标准列表视图。
     - **“按业务系统视图”**：以业务系统为分组，展示每个系统下的漏洞统计与列表，便于系统负责人统筹。
     - **“按责任人视图”**：以资产责任人为分组，展示每人名下需处理的漏洞，便于任务跟踪。
   - 点击对应标签即可切换到相应视图。在不同视图中，筛选与检索功能依然有效。

3. **执行操作**：
   - 在列表的每一行，通常提供“详情”按钮，点击可进入该漏洞的详情页面进行深度查看与处置。
   - 部分批量操作（如批量导出、批量修改状态）可能通过列表上方的功能按钮或勾选多条记录后出现的操作栏提供。待确认具体支持的批量操作。

### 4.2.2 脆弱性检测

本子模块负责漏洞的自动化发现与数据接入，是脆弱性管理流程的起点。

#### 4.2.2.1 脆弱性导入

**功能描述**：
支持通过上传标准化报告文件的方式，手动导入由其他扫描工具发现的漏洞数据，实现多源漏洞数据的统一管理。

**操作指南**：
1. 在“脆弱性管理”主菜单下，进入“脆弱性导入”页面。待确认具体菜单路径。
2. 点击“导入文件”或“上传报告”按钮。
3. 在弹出的文件选择器中，选择本地的漏洞报告文件。系统支持常见扫描工具的报告格式（待补充具体支持的文件格式，如 `.nessus`, `.xml`, `.csv`）。
4. 文件上传后，系统会进行解析，并在页面显示预览信息，可能包括：文件中的漏洞总数、受影响资产数、以及无法匹配到现有资产的条目列表。
5. 用户需确认预览信息，特别是未匹配资产的处置建议（如忽略或手动关联）。
6. 确认无误后，点击“开始导入”或“确认导入”。系统将解析数据，并与资产库进行匹配，新增或更新漏洞记录。
7. 导入完成后，页面会提示导入成功与失败的数量。用户可前往“脆弱性列表”查看导入的漏洞详情。

#### 4.2.2.2 脆弱性扫描任务管理

**功能描述**：
创建、配置、调度和执行自动化脆弱性扫描任务，对指定的资产范围进行定期或一次性的漏洞扫描。

**操作指南**：
1. **创建扫描任务**：
   a. 在“脆弱性管理”主菜单下，进入“扫描任务管理”页面。
   b. 点击“新建任务”按钮。
   c. 在弹窗中填写任务信息：
      - **任务名称**：输入易于识别的任务名称。
      - **扫描目标**：通过资产树、IP段或资产标签选择扫描范围。待确认具体选择控件。
      - **扫描策略**：从下拉列表中选择预定义的扫描策略（如全面扫描、快速扫描）。待补充策略库管理入口。
      - **扫描引擎**：从已接入的设备列表中选择执行扫描的引擎。
      - **调度方式**：选择“立即执行”或“周期执行”（支持按小时、天、周设置）。
      - **高级设置**：可配置扫描超时时间、并发线程数等参数（待补充具体参数列表）。
   d. 点击“确定”保存任务。若选择“立即执行”，任务将进入执行队列。

2. **管理扫描任务**：
   - **任务列表**：查看所有任务，列表显示任务名称、状态（等待中、扫描中、已完成、失败、已停止）、上次执行时间、下次执行时间等。
   - **任务操作**：
     - **启动/停止**：对处于“等待中”或“已停止”状态的任务执行“启动”；对“扫描中”的任务执行“停止”。
     - **编辑**：修改未执行或已停止的任务配置。
     - **删除**：删除任务记录。
     - **查看报告**：对于已完成的任务，可查看本次扫描发现的漏洞摘要报告。
     - **执行日志**：点击“日志”查看任务执行的详细过程与错误信息。

#### 4.2.2.3 脆弱性检测设备管理

**功能描述**：
对接和管理第三方漏洞扫描引擎或设备，确保扫描任务能够被正确调度和执行。

**操作指南**：
1. **添加扫描设备**：
   a. 在“脆弱性管理”主菜单下，进入“检测设备管理”页面。
   b. 点击“添加设备”按钮。
   c. 填写设备连接信息：
      - **设备名称**：自定义标识名称。
      - **设备类型**：选择引擎品牌/类型（如Nessus, OpenVAS等）。待确认支持的具体类型列表。
      - **连接地址**：输入引擎的API访问地址（URL）。
      - **认证方式**：选择“用户名/密码”或“API Key”，并输入对应凭证。
   d. 点击“测试连接”按钮，验证网络连通性与认证信息是否正确。
   e. 连接测试通过后，点击“保存”完成设备添加。

2. **管理设备**：
   - 在设备列表中，可查看所有已接入设备的状态（在线、离线）、版本、最后心跳时间等信息。
   - 支持操作：
     - **编辑**：修改设备连接信息。
     - **删除**：移除设备。若该设备有关联的扫描任务，需先解除关联。
     - **同步资产**：手动触发从该扫描引擎同步其管理的资产列表至本系统。

### 4.2.3 脆弱性详情

本子模块提供单个漏洞的完整信息展示与处置操作入口，是执行漏洞评估、修复跟踪与验证的核心界面。

#### 4.2.3.1 脆弱性详情

**功能描述**：
集中展示单个漏洞的全面信息，包括技术细节、风险评分、修复方案、受影响资产及处置历史等，为用户决策提供充分依据。

**操作指南**：
1. **进入详情页**：
   - 在“脆弱性列表”中，点击任意漏洞名称或操作列的“详情”按钮。

2. **查看详情信息**：
   - 页面通常分区域展示以下信息：
     - **漏洞概要**：漏洞名称、CVE/CNNVD编号、公开时间、CVSS评分/向量、风险等级（颜色标识）、当前状态。
     - **技术详情**：详细的漏洞描述、受影响的软件/组件/版本、攻击原理、可能造成的潜在影响。
     - **修复建议**：官方补丁链接、版本升级指南、临时缓解措施（如配置修改）。
     - **受影响资产列表**：以表格形式列出所有受此漏洞影响的资产，包含资产名称、IP地址、所属业务系统、责任人，以及该资产上此漏洞的单独状态。
     - **处置轨迹**：按时间倒序列出该漏洞所有的状态变更记录、任务下发记录、操作人及备注，实现操作可追溯。

#### 4.2.3.2 下发处置任务

**功能描述**：
针对漏洞一键生成整改工单，并自动关联所有受影响资产的责任人，将修复工作纳入标准化流程进行跟踪。

**操作指南**：
1. 在“脆弱性详情”页面的“操作”区域或页面顶部，找到并点击“下发处置任务”按钮。
2. 系统将自动生成一张整改工单，并关联此漏洞及所有受影响资产的责任人。
3. 在弹出的任务确认或编辑窗口中，可补充以下信息（待确认具体表单字段）：
   - **任务标题**：系统预填，通常包含漏洞名称，可手动编辑。
   - **处理要求**：详细描述修复步骤、验证要求或注意事项。
   - **紧急程度**：从下拉列表中选择高、中、低。
   - **期望完成时间**：通过日期时间选择器设置截止日期。
4. 点击“确认下发”或“提交”按钮。
5. 下发成功后：
   - 系统提示“处置任务下发成功”。
   - 该漏洞的状态通常自动变更为“修复中”。
   - 关联的整改工单将推送至相关责任人的待办列表（通常集成至协同工作中心或任务中心）。

#### 4.2.3.3 修复验证

**功能描述**：
对状态标记为“已修复”的漏洞，触发一次针对性的验证扫描，自动确认漏洞是否被成功修复，实现管理闭环。

**操作指南**：
1. **前提条件**：当前漏洞状态为“已修复”。
2. 在“脆弱性详情”页面，找到并点击“修复验证”按钮。
3. 系统将弹出确认框，提示即将发起一次针对该漏洞的验证扫描（通常仅检查原漏洞点）。
4. 点击“确认”后，系统自动向发现该漏洞的原扫描引擎提交一个验证任务。
5. **查看验证结果**：
   - 验证任务执行期间，漏洞状态可能显示为“验证中”。
   - 验证完成后，系统会根据扫描结果自动更新漏洞状态：
     - **验证通过**：扫描结果未发现该漏洞，状态更新为“已验证修复”，处置流程闭环。
     - **验证未通过**：扫描结果仍发现该漏洞存在，状态回退为“待处理”或“修复失败”，并可能生成通知提醒相关责任人。
6. 验证过程的日志与结果详情可在详情页的“处置轨迹”或专门的“验证记录”中查看。

## 4.3 常见问题与处理

- **Q：新建的扫描任务始终无法启动？**
  A：请按以下步骤排查：1）检查所选“扫描引擎”设备状态是否为“在线”；2）检查“扫描目标”中的资产IP地址是否可达；3）查看任务“执行日志”获取具体错误信息。常见原因为引擎认证失败或网络策略限制。

- **Q：导入漏洞报告后，为何有些资产显示“未关联”？**
  A：这是因为报告中提供的资产标识（如IP、主机名）未在系统的资产库中找到完全匹配项。请前往“资产管理”模块确认资产已录入，或检查导入文件的资产信息格式是否正确。

- **Q：下发了处置任务，但责任人声称未收到通知？**
  A：首先，在漏洞详情页的“处置轨迹”中确认任务已成功下发。其次，确认系统集成的通知渠道（如站内信、邮件、即时通讯）配置正常。最后，可联系系统管理员检查协同工作中心的流程配置。

- **Q：点击“修复验证”后，长时间无结果？**
  A：验证扫描依赖原扫描引擎。请检查：1）该引擎设备是否在线；2）待验证的资产当前是否可被引擎访问（网络策略、主机状态）；3）通过引擎管理界面查看验证任务队列状态。

- **Q：在“按责任人视图”下，能否批量分配漏洞？**
  A：待确认。该功能取决于系统设计。如有需要，请查阅系统更新日志或联系管理员。

## 4.4 风险提示

1. **扫描操作风险**：全端口扫描或深度检测可能对目标系统的性能和稳定性产生影响，甚至可能触发安全防护设备的告警。请在获得授权后，于业务低峰期执行，并提前通知相关业务负责人。
2. **漏洞修复风险**：修复高危漏洞，尤其是涉及系统补丁或配置变更的操作，必须在测试环境中充分验证，制定回滚方案，避免直接在生产环境实施导致业务中断。
3. **数据安全风险**：脆弱性数据详细揭示了资产的安全弱点，属于敏感信息。必须通过系统权限机制严格控制访问范围，仅对授权的安全管理员和资产管理员开放，并禁止未加密的外发。
4. **漏洞库时效风险**：扫描引擎的漏洞检测能力依赖于其插件库的更新。为确保能发现最新漏洞，请定期关注并升级扫描引擎的漏洞插件，同时关注系统内置漏洞知识库的更新情况。
