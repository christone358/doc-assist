## NextAgent Doc Assistant 技能管理模块用户使用手册 (修订版)

### 第4章 软件操作指南

#### 4.1 技能管理模块

技能管理模块是 NextAgent Doc Assistant 系统的核心扩展框架，对应系统架构中的 **Skill 框架模块**。它负责管理所有“技能”（Skill）的全生命周期。技能是系统执行具体任务（如生成用户手册、分析代码结构、绘制流程图）的能力单元。本模块为系统管理员提供了集中化的技能管控界面，确保系统能力透明、可控且易于扩展。

**模块入口**：`需产品确认，通常在系统管理或技能中心菜单下。`

##### 4.1.1 查看技能列表

**4.1.1.1 功能概述**
本功能是技能管理的总览入口，用于集中展示系统中所有已注册和可用的技能。通过此列表，管理员可以快速掌握系统的整体能力构成，了解每个技能的基本属性（如名称、描述、当前状态），从而为后续的启用、禁用或排查问题提供决策依据。其核心价值在于提供了系统技能资产的全局可视性，是进行技能运维和容量评估的基础。

**4.1.1.2 前置条件**
- 用户已成功登录 NextAgent Doc Assistant 系统。
- 用户拥有访问技能管理模块的权限（通常为管理员角色）。

**4.1.1.3 操作步骤**
1.  登录系统后，在主菜单栏选择 **【系统管理】** > **【技能管理】**。`（菜单路径待确认）`
2.  系统将跳转至“技能列表”页面。
3.  页面以表格形式展示所有技能，通常包含以下列：`（界面字段待确认）`
    - **技能名称**：技能的标识名称。
    - **技能描述**：对该技能功能的简要说明。
    - **状态**：显示“已启用”或“已禁用”。
    - **操作**：提供对该技能进行管理的按钮，如“启用/禁用”、“详情”。

**4.1.1.4 输出/结果**
- 成功加载后，页面将显示完整的技能列表。
- 用户可以通过列表了解每个技能的基本信息和当前可用状态。

**4.1.1.5 异常处理**
| 异常现象 | 可能原因 | 处理方法 |
| :--- | :--- | :--- |
| 页面提示“暂无数据”或列表为空。 | 1. 系统未成功加载任何技能。<br>2. 当前过滤器筛选结果为空。 | 1. 检查系统服务是否正常，技能目录配置是否正确。<br>2. 清除可能的筛选条件。 |
| 页面提示“权限不足”。 | 当前登录账号无权限访问此模块。 | 联系系统管理员获取相应权限。 |

##### 4.1.2 启用/禁用技能

**4.1.2.1 功能概述**
本功能提供了对单个技能可用性的实时、细粒度控制。管理员可以根据运维需要（如技能出现故障、进行版本升级）或业务策略（如临时关闭某项文档生成功能），动态地启用或禁用特定技能。此操作直接影响系统核心（Agent模块）的调度决策，被禁用的技能将不会被调用。该功能的核心价值在于保障系统服务的灵活性与稳定性，允许管理员在不重启服务的情况下快速隔离问题技能或调整系统能力集。

**4.1.2.2 前置条件**
- 已进入“技能列表”页面。
- 目标技能存在且状态明确。

**4.1.2.3 操作步骤**
1.  在“技能列表”页面，找到需要操作的目标技能。
2.  在目标技能所在行的“操作”列，点击 **【禁用】** 按钮（若技能当前为启用状态）或 **【启用】** 按钮（若技能当前为禁用状态）。`（按钮文案待确认）`
3.  系统可能会弹出确认对话框，提示操作影响（例如：“禁用后，系统将无法使用此技能”）。
4.  在确认对话框中，点击 **【确定】** 按钮以执行操作。

**4.1.2.4 输出/结果**
- 操作成功后，页面技能列表中该技能的“状态”列将立即更新为“已禁用”或“已启用”。
- 系统可能给出短暂的成功提示，如“技能状态已更新”。`（提示文案待确认）`
- 状态变更即刻生效。对于已禁用的技能，后续的用户请求将不会被分配至该技能执行。

**4.1.2.5 异常处理**
| 异常现象 | 可能原因 | 处理方法 |
| :--- | :--- | :--- |
| 点击按钮无反应或状态未更新。 | 1. 网络通信异常。<br>2. 后端服务处理失败。 | 1. 检查网络连接，刷新页面后重试。<br>2. 查看系统日志或联系技术支持。 |
| 提示“操作失败，技能不存在”。 | 技能可能已被删除或配置文件损坏。 | 检查技能配置文件或联系系统管理员。 |

**4.1.2.6 警告/注意**
- **注意**：禁用核心技能（如文档生成类技能）可能会影响系统的主要功能，请谨慎操作。
- **注意**：状态变更实时生效，无需重启服务。

##### 4.1.3 查看技能详情

**4.1.3.1 功能概述**
本功能用于深入探查特定技能的元信息，这些信息来源于该技能的 `skill.md` 定义文件。详情页面不仅展示技能的基本描述，更会揭示其“能力边界”、输入输出规范以及配置参数。对于管理员而言，这是在技能出现异常或需要评估其适用性时进行诊断和理解的关键窗口；对于使用者或开发者，这是了解技能确切能力、确保正确调用的重要参考。其业务价值在于提升了技能使用的透明度和准确性，减少了因误解技能能力而导致的调用错误。

**4.1.3.2 前置条件**
- 已进入“技能列表”页面。

**4.1.3.3 操作步骤**
1.  在“技能列表”页面，找到需要查看详情的技能。
2.  在该技能所在行的“操作”列，点击 **【详情】** 或 **【查看】** 按钮。`（按钮文案待确认）`
3.  系统将打开一个侧边栏或新页面，展示该技能的详细信息。

**4.1.3.4 输出/结果**
- 页面展示技能的完整元信息，内容解析自该技能的 `skill.md` 文件，可能包括：`（详情字段待确认）`
    - **技能标识符 (ID)**：系统内部调用的唯一标识。
    - **技能名称**：显示名称。
    - **详细描述**：比列表更详尽的功能说明。
    - **能力边界**：明确说明该技能擅长处理和不擅长处理的任务类型。
    - **输入/输出示例**：展示调用该技能所需的典型输入和预期输出格式。
    - **版本**：技能的版本号。

**4.1.3.5 异常处理**
| 异常现象 | 可能原因 | 处理方法 |
| :--- | :--- | :--- |
| 点击详情后页面无内容或报错。 | 技能的元信息文件 (`skill.md`) 缺失或格式错误。 | 联系技能开发者或系统管理员检查该技能的配置文件。 |

##### 4.1.4 扩展自定义技能（高级功能）

**4.1.4.1 功能概述**
本功能体现了系统 **“支持用户自定义扩展 Skill”** 的核心特性，面向开发者或高级用户开放。它允许通过创建符合框架标准的技能包并放置到指定目录，来无缝扩展系统的能力边界。系统后台的“Skill 自动发现和加载”机制会识别新技能并使其立即可用。此功能的使用场景包括：为特定业务领域（如生成某种特殊报表）添加专用技能，或集成外部工具与服务。其核心业务价值在于赋予了系统强大的可扩展性和适应性，使系统能力能够伴随业务需求成长，而非受限于初始功能集。

**4.1.4.2 前置条件**
- 用户具有服务器文件系统的访问权限（此操作通常不通过Web UI完成）。
- 了解 Skill 框架的开发规范。

**4.1.4.3 操作步骤**
`（此部分为系统级操作，非Web界面操作）`
1.  **开发技能**：按照 `Skill 框架模块` 定义的接口和规范，编写技能执行逻辑和 `skill.md` 元信息文件。
2.  **放置文件**：将技能相关的文件包放置到系统配置的技能加载目录下（例如 `./skills/`）。`（目录路径待确认）`
3.  **触发加载**：系统会在启动时自动扫描目录并加载技能。对于已运行的系统，可能需要通过 **【刷新技能列表】** 功能或重启服务来使新技能生效。`（Web UI上是否有刷新按钮待确认）`

**4.1.4.4 输出/结果**
- 操作成功后，新技能将出现在“技能列表”中，状态默认为“已启用”。
- Agent 在处理用户请求时，可以将任务调度给新添加的技能。

**4.1.4.5 异常处理**
| 异常现象 | 可能原因 | 处理方法 |
| :--- | :--- | :--- |
| 新技能未出现在列表中。 | 1. `skill.md` 文件格式不符合规范。<br>2. 技能文件未放在正确目录。<br>3. 系统未重新加载技能列表。 | 1. 检查 `skill.md` 文件的语法和必填字段。<br>2. 确认技能存放目录。<br>3. 尝试在管理界面执行“刷新”操作或重启服务。 |
| 新技能加载失败，状态为“错误”。 | 技能的逻辑代码存在bug或依赖缺失。 | 查看系统错误日志，根据报错信息修复技能代码。 |

**4.1.4.6 警告/注意**
- **警告**：添加未经测试的自定义技能可能存在稳定性风险，建议先在测试环境中验证。
- **注意**：技能文件的命名和结构必须严格遵守框架规范，否则无法被正确识别和加载。
