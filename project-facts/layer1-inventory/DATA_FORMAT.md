# 清单层数据格式设计

清单层（Layer 1 - Manifest）提供项目的高层概览，列举项目的主要构成要素。

## 数据格式规范

### 1. 用例清单 (usecases.md)

**格式**: Markdown 结构化列表

```markdown
# 用例清单

## 概述
项目支持的所有用例列表，按功能模块分类。

## 功能模块 A
### 用例分组 1
- UC-001: 用例名称 1 - *简要说明*
- UC-002: 用例名称 2 - *简要说明*

### 用例分组 2
- UC-003: 用例名称 3 - *简要说明*

## 功能模块 B
...

## 统计信息
| 模块 | 用例数 | 状态 |
|------|--------|------|
| 模块A | 5 | 完成 |
| 模块B | 3 | 进行中 |
```

**数据结构**:
```json
{
  "type": "usecases_manifest",
  "version": "1.0",
  "items": [
    {
      "id": "UC-001",
      "name": "用例名称",
      "module": "模块名称",
      "description": "简要说明",
      "status": "active|deprecated|draft"
    }
  ],
  "total_count": 10,
  "last_updated": "2026-03-16T00:00:00Z"
}
```

### 2. 功能模块清单 (modules.md)

**格式**: Markdown 层级列表

```markdown
# 功能模块清单

## 系统架构概述
[系统整体架构说明]

## 核心模块

### 1. 认证与授权模块
- **模块ID**: MOD-AUTH
- **简介**: 处理用户认证和权限管理
- **子模块**:
  - MOD-AUTH-USER: 用户管理
  - MOD-AUTH-ROLE: 角色管理
  - MOD-AUTH-PERM: 权限管理
- **技术栈**: Python, JWT, OAuth2

### 2. 数据处理模块
- **模块ID**: MOD-DATA
- **简介**: 处理项目数据的存储和检索
- ...

## 支持模块
...

## 模块依赖关系
[模块之间的依赖关系图或说明]
```

**数据结构**:
```json
{
  "type": "modules_manifest",
  "version": "1.0",
  "modules": [
    {
      "id": "MOD-AUTH",
      "name": "认证模块",
      "description": "处理认证和授权",
      "level": 0,
      "submodules": ["MOD-AUTH-USER", "MOD-AUTH-ROLE"],
      "status": "active",
      "tech_stack": ["Python", "JWT"]
    }
  ]
}
```

### 3. 用户角色清单 (users.md)

**格式**: Markdown 表格和说明

```markdown
# 用户角色清单

## 用户角色概览

| 角色 | 描述 | 主要权限 | 用例数 |
|------|------|---------|--------|
| 管理员 | 系统管理员 | 所有权限 | 10 |
| 编辑 | 文档编辑者 | 创建、编辑、删除文档 | 15 |
| 查看者 | 只读用户 | 浏览文档 | 5 |

## 详细描述

### 管理员
- **权限范围**: 完全控制系统
- **职责**: 系统配置、用户管理、数据维护
- **典型用例**: UC-001, UC-002

### 编辑
...
```

**数据结构**:
```json
{
  "type": "users_manifest",
  "version": "1.0",
  "roles": [
    {
      "id": "ROLE-ADMIN",
      "name": "管理员",
      "description": "系统管理员",
      "permissions": ["read", "write", "delete", "admin"],
      "usecases": ["UC-001", "UC-002"]
    }
  ]
}
```

### 4. 风险清单 (risks.md)

**格式**: Markdown 风险表和说明

```markdown
# 风险清单

## 识别的风险

| ID | 风险项 | 等级 | 概率 | 影响 | 缓解措施 |
|----|--------|------|------|------|---------|
| R-001 | 性能问题 | 高 | 中 | 高 | 性能测试、优化 |
| R-002 | 安全漏洞 | 高 | 低 | 高 | 代码审查、安全审计 |
| R-003 | 需求变更 | 中 | 高 | 中 | 变更管理流程 |

## 详细描述

### R-001: 性能问题
- **描述**: 系统响应时间可能超过 SLA 要求
- **根本原因**: 数据量大、算法复杂
- **缓解措施**: 实施缓存、数据库优化、算法改进
- **所有者**: 技术负责人
- **更新日期**: 2026-03-16
```

**数据结构**:
```json
{
  "type": "risks_manifest",
  "version": "1.0",
  "risks": [
    {
      "id": "R-001",
      "title": "性能问题",
      "severity": "high",
      "probability": "medium",
      "impact": "high",
      "mitigation": "性能测试和优化",
      "owner": "技术负责人",
      "status": "active"
    }
  ]
}
```

## 验证规则

- 清单项应包含基本标识和描述
- 每个项的 ID 应该唯一
- 状态字段值应为：active, deprecated, draft
- 层级关系应该无循环依赖
- 更新时间应为有效的 ISO 8601 格式

## 维护指南

- 定期审查和更新清单内容
- 当项目阶段变更时，及时更新相关项
- 保持与核心信息层的一致性
- 记录变更历史和原因
